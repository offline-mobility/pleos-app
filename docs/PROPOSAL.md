# 기획서 초안 (접수양식 02 항목 기준)

앱명(가칭): Offline Mobility

## 1. 앱 한 줄 소개

기지국과 인터넷이 끊긴 재난·비상 상황에서, 정차한 차량끼리 소리와 빛으로 구조 메시지를 주고받고 다음 차량으로 이어 전달하는 차량용 오프라인 비상 신호 앱.

## 2. 기획 배경

**재난 때 통신망은 먼저 끊긴다.**

| 사례 | 통신 피해 |
|---|---|
| 2017 허리케인 마리아 (푸에르토리코) | 기지국 95.2% 중단, 78개 지자체 중 48곳 100% 중단 (FCC) |
| 2023 마우이 라하이나 산불 | 서마우이 기지국 21개 중 19개 중단, 일부 911 연결 불가 (FCC) |
| 2023 튀르키예 지진 | 피해 지역 기지국 약 3,300개 중 절반 첫날 중단 (Turkcell) |
| 2024 노토반도 지진 | 최대 839국 정파 (일본 총무성) |
| 2025.3 영남 대형산불 | 울진 SKT 전면 중단으로 재난로밍 발령, 영양 일대 무선통신 두절 |
| 2018 KT 아현국사 화재 | 서울 5개 구 유·무선 불통. 119 신고가 안 돼 지나가는 차를 붙잡고 전화를 빌렸고, 연결까지 20분 넘게 걸림 |

원인은 대부분 정전과 전송로 단절이다. 이동식 기지국은 화재·붕괴 현장 안으로 들어가기 어렵다.

**고립된 사람은 차 안에 있다.**
- 라하이나 산불 사망자 97명 중 15명이 차량 안에서 발견됐다 (마우이 경찰 사후보고서).
- 2025 영덕에서는 대피 차량 폭발로 3명이 숨졌다. 영양에서는 통신이 끊긴 마을을 차로 확인하러 나선 이장 부부가 숨졌다.
- 오송 궁평2지하차도에서는 차량 17대가 침수됐다.
- 전시도 같다. 민방공 공습경보 행동요령은 운행 중인 차량에 "가까운 빈터나 도로 우측에 정차"하도록 한다. 경보가 울리면 도로마다 정차 차량의 행렬이 생긴다.

**기존 대안은 망이 살아 있어야 하거나 일반인이 쓸 수 없다.**

| 수단 | 한계 |
|---|---|
| 재난로밍·재난 와이파이 | 다른 통신사 망이나 유선망이 살아 있어야 함 |
| 재난안전통신망(PS-LTE) | 경찰·소방 등 기관 전용 |
| 위성 SOS (iPhone, Pixel) | 국내 미지원. 하늘이 트인 실외에서만 동작 |
| 메시 무전기 (Meshtastic 등) | 별도 기기를 미리 사서 갖고 있어야 함 |
| 경적·상향등 | 의미가 표준화되어 있지 않아 "무슨 일인지" 전달 불가 |

국내 등록 차량은 2,667만 대(2026.6)다. 차량에는 휴대전화보다 수천 배 큰 배터리, 멀리 보이는 외부 조명, 실내 스피커와 마이크가 이미 있다. 이 장비를 통신망 없이 쓰는 방법이 없다는 점이 이 앱이 해결하려는 문제다.

## 3. 앱 주요 기능 및 차량 특화 요소

**① 음향 데이터 통신 — 차량 스피커로 보내고 마이크로 받는다**
- 15종 구조 메시지(긴급 구조, 응급 환자, 고립, 화재, 가스 누출, 침수, 노약자 동승, 식수, 연료·전력, 도로 차단, 통행 가능, 대피소, 구조대 접근, 전원 안전, 수신 확인)와 탑승 인원을 1.7초 길이의 소리 한 묶음으로 보낸다.
- 수신 차량은 마이크로 받아 화면에 문장으로 띄운다. 사람이 신호를 해석할 필요가 없다.
- 오류 정정(Reed-Solomon)과 오류 검출(CRC)을 넣어, 소음 속에서도 잘못된 메시지가 표시되지 않는다.

**② 표준 조난 점멸 — 차량이 지원하는 외부 조명 자동 선택**
- 위급 메시지는 SOS 점멸을 쓴다. 시간 간격은 미국 해안경비대 전자 조난등 기준(46 CFR 161.013-7)을 따른다.
- 일반 메시지는 국제 산악 조난 신호(분당 6회)를 쓰고, 응답은 분당 3회로 보낸다.
- 구조대가 접근하면 이중 점멸로 정확한 차량 위치를 알린다.
- 차량마다 제어 가능한 조명이 다르므로 Capability API로 확인해 조명을 고른다. 후방 안개등이 있으면 상향등과 후방 안개등을 점멸하고, 하향등은 켜둔다. 없으면 하향등과 상향등을 함께 점멸한다. 하향등이 켜질 때 미등도 같이 켜져 뒤쪽에도 신호가 간다.
- 점멸 명령을 보낸 뒤 실제 점등 상태를 다시 읽어 확인한다. 신호가 끝나면 모든 조명을 원래 상태로 되돌린다.
- 앱이 없는 사람이나 헬기, 드론도 알아볼 수 있는 국제 관례를 따른다. 일정한 1~2Hz 점멸은 비상등으로 오인되므로 쓰지 않는다.

**③ 차량 간 중계 — 정차 차량 행렬이 통신망이 된다**
- 신호를 받은 차량은 무작위로 1.5~6초를 기다렸다가 같은 메시지를 다시 보낸다. 최대 3대까지 이어진다.
- 같은 메시지는 한 번만 중계해 신호가 무한히 반복되지 않게 한다.
- 내가 보낸 메시지가 다른 차를 거쳐 돌아오면 "중계 확인"으로 표시한다. 메시지가 전달됐다는 간접 확인이 된다.

**④ 안전 잠금**
- 기어가 P단일 때만 송신한다. P단에서 벗어나면 즉시 중단하고 조명을 원래 상태로 되돌린다.
- 등화관제 모드: 야간 공습경보 때는 행동요령에 따라 외부 조명을 끄고 소리로만 통신한다.
- 조난 점멸 패턴은 실제 조난 상황에만 쓰도록 메시지 종류와 연결해 둔다.

**차량 특화 요소**

| 차량 자원 | 활용 |
|---|---|
| 외부 조명 (Vehicle SDK Light) | 수 km 밖에서 보이는 조난 점멸 |
| 실내 스피커·마이크 | 별도 장비 없는 데이터 송수신 |
| 기어 상태 (Vehicle SDK Gear) | 정차 확인, 안전 잠금 |
| 대용량 배터리 | 휴대전화가 꺼진 뒤에도 신호 유지 |
| 도로 위 위치 | 정차 차량 행렬이 그대로 중계망이 됨 |

## 4. 주요 사용 시나리오

**시나리오 A — 산불로 고립된 산간 도로**
1. 산불로 도로가 막히고 휴대전화가 끊긴다. 차량 5대가 1km 구간에 멈춰 있다.
2. 맨 앞 차량 A의 동승자가 연기를 마시고 쓰러진다. 운전자가 P단 상태에서 `응급 환자 · 2명`을 누른다.
3. A는 소리 신호를 3회 보내고, 상향등과 후방 안개등으로 SOS를 점멸한다.
4. 뒤쪽 차량 B가 신호를 받는다. 화면에 "응급 환자 발생 · 2명 · 직접 수신"이 뜨고, B가 자동으로 중계한다.
5. C, D를 거쳐 메시지가 진입로에 도착한다. 대기 중이던 소방차 옆 차량 E의 화면에 "응급 환자 · 3대 거쳐 중계"가 표시된다.
6. A의 화면에는 "내 신호 중계 확인"이 뜬다. 구조대가 접근하면 A는 `구조대 접근 중` 이중 점멸로 위치를 알린다.

**시나리오 B — 공습경보로 정차한 도로**
1. 공습경보가 울리고 차량들이 도로 우측에 정차한다. 기지국은 정전으로 멈췄다.
2. 야간이라 등화관제 모드를 켠다. 조명은 꺼지고 소리 신호만 쓴다.
3. 노약자를 태운 차량이 `노약자·어린이 동승 · 4명`을 보낸다. 주변 차량이 중계하고, 대피를 돕는 민방위 요원 차량이 받는다.
4. 경보가 해제되면 대피소를 확인한 차량이 `대피소 확인`을 보내 다른 차량에 알린다.

## 5. 개발 계획

**구조**

```
[UI · Compose]  메시지 선택 / 송신 / 수신함 / 안전 상태
      │
[ViewModel]  송수신 조율, 중계 스케줄, 안전 잠금
      │
 ┌────┼─────────────┬──────────────────┐
[음향 모뎀]       [조명 신호]         [차량 연동]
 프레임 부호화     SOS·비컨 패턴       Pleos Vehicle SDK
 16-FSK 변조       조명 전환·복원       Light / Gear
 처프 동기·복조    등화관제 차단        Capability 확인
 RS(14,8) 정정
      │
 AudioTrack(USAGE_ALARM, 오디오 포커스) / AudioRecord(UNPROCESSED)
```

**음향 프레임 설계**

| 항목 | 값 |
|---|---|
| 정보 | 메시지 4bit · 인원 4bit · 차량 ID 8bit · 순번 4bit · 중계 횟수 2bit · 버전 2bit + CRC-8 |
| 오류 정정 | Reed-Solomon (14, 8) / GF(16). 오류 3개 또는 소거 6개 정정 |
| 변조 | 16-FSK, 1,500~3,437Hz, 125Hz 간격, 홀짝 심볼 62.5Hz 엇갈림, 심볼 80ms + 보호 구간 20ms |
| 동기 | 1~5kHz 선형 처프 256ms, FFT 정합 필터 |
| 복조 | 심볼별 Goertzel, 신뢰도 낮은 심볼을 소거로 처리해 재복호 (GMD 복호) |
| 길이 | 프레임 1.7초, 3회 반복 송신 |
| 수신 처리 | 마이크 잡음 억제·자동 음량·반향 제거 해제, 800Hz~6kHz 대역 통과, 44.1kHz 기기 호환 |

대역은 가청 1.5~3.5kHz를 쓴다. 차량 핸즈프리 마이크 경로가 7kHz 이하로 설계되는 경우가 많고(ITU-T P.1110), 공기 흡수가 3kHz에서 0.015dB/m로 19kHz(0.38dB/m)보다 25배 작다(ISO 9613-1). 엔진·노면 소음은 저역에 몰려 있다. 재난 상황에서는 소리가 들리는 편이 오히려 낫다.
변조 방식 비교 실측 연구(Putz et al., ACM TIoT 2026)에서 처프 계열 방식은 40m에서 98% 이상 성공했고, 다중 톤 방식(ggwave 가청 모드)은 주변 소음 속에서 실패했다. 이 앱은 처프로 동기를 잡고 심볼당 단일 톤만 보내 톤 하나에 송신 전력을 모은다.

시뮬레이션 결과 (잔향 2경로, 엔진 저주파, 백색 잡음, 프레임당 40회 시험):

| 전대역 SNR | 0dB | -5dB | -10dB | -15dB | -20dB |
|---|---|---|---|---|---|
| 수신 성공률 | 100% | 100% | 100% | 100% | 27.5% |

**Pleos SDK·API 사용 계획**

| 기능 | API | 퍼미션 |
|---|---|---|
| 조명 지원 여부 | `Light.check{HighBeam,RearFog,…}LightSwitchCapabilities` | `CAR_LIGHTS` |
| 원래 조명 상태 저장 | `Light.get{HighBeam,RearFog}LightSwitch` | `CAR_LIGHTS` |
| 조난 점멸 | `Light.set{HighBeam,LowBeam,RearFog,TailLamp}LightSwitch(ON/OFF)` | `CONTROL_CAR_LIGHTS` (App Market 사전 승인 대상) |
| 실제 점등 확인 | `Light.getCurrent{HighBeam,LowBeam,RearFog,TailLamp}LightState` | `CAR_LIGHTS` |
| 정차 확인 | `Gear.getCurrentGearSelectionState`, `registerGearSelection` | `CAR_DRIVE` |
| 소리 송신 | Android `AudioTrack`, 오디오 포커스 요청·반납 | — |
| 소리 수신 | Android `AudioRecord` (UNPROCESSED 우선) | `RECORD_AUDIO` |

**현재 구현 상태**
- 완료: 음향 모뎀(송신·수신·오류 정정), 조명 패턴과 차량별 조명 선택, 중계 정책, 안전 잠금, 등화관제 모드, Pleos Vehicle SDK 연동(Light·Gear), 차량용 화면, 단위 테스트 37개.
- Pleos Connect Emulator v2.1.0 검증 결과:

| 항목 | 결과 |
|---|---|
| Vehicle SDK 연결, 기어 조회 | 정상 (P단 표시) |
| 조명 제어 권한 | 차량 서비스가 `CONTROL_CAR_LIGHTS` 검증 후 상향등·하향등·미등 제어 성공 |
| 조명 지원 확인 | 에뮬레이터 차종은 후방·전방 안개등 미지원 → 하향등+상향등 점멸로 자동 전환 |
| SOS 점멸 리듬 | Virtual Console 차량 상태에서 점 0.33초 · 문자 간격 2초 · 선 1초 · 주기 14초 확인 |
| 안전 잠금 | 송신 중 Virtual Console에서 기어를 D로 바꾸자 같은 시각에 송신 중단, 조명 원상 복구 |
| 조명 복구 | 신호 전 미등 켜짐 상태 → 신호 후 미등 켜짐 상태로 복구 |
| 음향 수신 | 합성한 타 차량 신호를 앱 수신기로 해독 (SNR 36dB, 오류 0) |
| 오디오 출력 | 차량 오디오 포커스(USAGE_ALARM) 획득 |

- 공기 중 음향 실측 (노트북 스피커 → 같은 노트북 마이크 약 20cm → Pleos 에뮬레이터 → 앱 수신기, 실제 오디오 경로):

| 조건 | 결과 |
|---|---|
| 조용한 실내, 재생 볼륨 0dB ~ -54dB (6dB 단계, 단계당 5개) | 50/50 해독, 오류 정정 0개 |
| 재생 볼륨 -60dB (수신 신호가 실내 소음 수준) | 3/5 해독 |
| 저주파 잡음(도로·바람 소음 성격) 동시 재생 | 20/20 해독 |
| 백색 잡음 동시 재생, 전대역 SNR +4.3 ~ -13.7dB | 12/12 해독 |
| 백색 잡음 동시 재생, 전대역 SNR -19.7dB | 0/3 해독 |

실측 한계(-13.7dB 성공, -19.7dB 실패)는 시뮬레이션 결과(-15dB 100%, -20dB 27.5%)와 일치한다. 조용한 환경에서 최대 볼륨 대비 54dB의 링크 여유가 있다.
- 에뮬레이터에서 확인할 수 없는 항목: 상향등 실제 점등은 에뮬레이터에 차량 제어기 모델이 없어 스위치 명령 수락까지만 확인된다. 차량 간 실외 전달 거리는 실차에서 측정해야 한다.
- 진행: 실차·실외 환경 거리별 음향 측정, 측정값에 맞춘 변조 파라미터 조정.
- 운용 조건: 차량 전원(ACC 이상)이 켜져 있어야 한다. 차량 간 거리가 멀면 창문을 조금 열어야 수신 거리가 늘어난다. 차체 차음이 25~35dB에 이르기 때문이다.
- 2차 PT까지: 시나리오 A·B 시연 영상, 연료·배터리 잔량 기반 신호 지속 시간 예측, 수신 메시지 음성 안내, 평시 점검·훈련 모드.

## 6. 기대효과 및 발전 가능성

- **사용자 가치:** 통신이 끊긴 순간에도 차 안에서 구조 요청을 보낼 수 있고, 내 신호가 전달됐는지 확인할 수 있다. 별도 장비 없이 이미 가진 차량으로 해결한다.
- **탑재 방식:** 차량 기본 안전 기능으로 탑재하는 것을 목표로 한다. 같은 앱을 가진 차량이 늘어날수록 중계망이 촘촘해진다.
- **평시 사용:** 월 1회 신호 점검(조명·스피커 자가 진단)과 민방위 훈련일 신호 연습 모드를 둔다. 둘 다 통신망 없이 동작한다.
- **확장:**
  - LTE-V2X(C-ITS 단일 표준, 2023.12 결정)가 보급되면 같은 메시지 체계를 V2X 메시지로 옮길 수 있다.
  - 구조기관 차량과 드론을 수신 노드로 쓸 수 있다.
  - 스마트폰 카메라로 조난 점멸을 해독하는 보조 앱을 붙일 수 있다.
