# 기획서 초안 (접수양식 02 항목 기준)

앱명(가칭): Offline Mobility

## 1. 앱 한 줄 소개

기지국과 인터넷이 끊긴 재난·비상 상황에서, 정차한 차량끼리 소리와 빛으로 구조 메시지를 주고받고 다음 차량으로 이어 전달하는 차량용 오프라인 비상 신호 앱.

## 2. 기획 배경

**재난 때 통신망은 먼저 끊긴다.**

| 사례 | 통신 피해 |
|---|---|
| 2017 허리케인 마리아 (푸에르토리코) | 기지국 95.2% 중단, 78개 지자체 중 48곳 100% 중단 (FCC) |
| 2023 마우이 라하이나 산불 | 서마우이 기지국 21개 중 19개 중단, 일부 911 연결 불가 (FCC) |
| 2023 튀르키예 지진 | 피해 지역 기지국 약 3,300개 중 절반 첫날 중단 (Turkcell) |
| 2024 노토반도 지진 | 최대 839국 정파 (일본 총무성) |
| 2025.3 영남 대형산불 | 울진 SKT 전면 중단으로 재난로밍 발령, 영양 일대 무선통신 두절 |
| 2018 KT 아현국사 화재 | 서울 5개 구 유·무선 불통. 119 신고가 안 돼 지나가는 차를 붙잡고 전화를 빌렸고, 연결까지 20분 넘게 걸림 |

원인은 대부분 정전과 전송로 단절이다. 이동식 기지국은 화재·붕괴 현장 안으로 들어가기 어렵다.

**고립된 사람은 차 안에 있다.**
- 라하이나 산불 사망자 97명 중 15명이 차량 안에서 발견됐다 (마우이 경찰 사후보고서).
- 2025 영덕에서는 대피 차량 폭발로 3명이 숨졌다. 영양에서는 통신이 끊긴 마을을 차로 확인하러 나선 이장 부부가 숨졌다.
- 오송 궁평2지하차도에서는 차량 17대가 침수됐다.
- 전시도 같다. 민방공 공습경보 행동요령은 운행 중인 차량에 "가까운 빈터나 도로 우측에 정차"하도록 한다. 경보가 울리면 도로마다 정차 차량의 행렬이 생긴다.

**기존 대안은 망이 살아 있어야 하거나 일반인이 쓸 수 없다.**

| 수단 | 한계 |
|---|---|
| 재난로밍·재난 와이파이 | 다른 통신사 망이나 유선망이 살아 있어야 함 |
| 재난안전통신망(PS-LTE) | 경찰·소방 등 기관 전용 |
| 위성 SOS (iPhone, Pixel) | 국내 미지원. 하늘이 트인 실외에서만 동작 |
| 메시 무전기 (Meshtastic 등) | 별도 기기를 미리 사서 갖고 있어야 함 |
| 경적·상향등 | 의미가 표준화되어 있지 않아 "무슨 일인지" 전달 불가 |

국내 등록 차량은 2,667만 대(2026.6)다. 차량에는 휴대전화보다 수천 배 큰 배터리, 멀리 보이는 외부 조명, 실내 스피커와 마이크가 이미 있다. 이 장비를 통신망 없이 쓰는 방법이 없다는 점이 이 앱이 해결하려는 문제다.

## 3. 앱 주요 기능 및 차량 특화 요소

**① 음향 데이터 통신 — 차량 스피커로 보내고 마이크로 받는다**
- 19종 구조 메시지(긴급 구조, 응급 환자, 고립, 화재, 침수, 가스·위험물, 붕괴·낙석, 화생방·방사능, 추위·저체온, 노약자 동승, 식수, 식량, 약, 연료·전력, 도로 차단, 통행 가능, 대피소, 구조대 접근, 전원 안전)와 탑승 인원, GPS 위치(약 40m 격자)를 3.3초 길이의 소리 한 묶음으로 보낸다.
- 수신 차량은 마이크로 받아 화면에 "응급 환자 2명, 북동쪽 약 300m"처럼 문장으로 띄운다. 사람이 신호를 해석할 필요가 없다.
- GPS는 위성 신호라 통신이 끊겨도 동작한다. 위치를 보낼지는 보내기 전 확인 화면에서 고른다.
- 오류 정정(Reed-Solomon)과 오류 검출(CRC)을 넣어, 소음 속에서도 잘못된 메시지가 표시되지 않는다.

**② 표준 조난 점멸 — 차량이 지원하는 외부 조명 자동 선택**
- 위급 메시지는 SOS 점멸을 쓴다. 시간 간격은 미국 해안경비대 전자 조난등 기준(46 CFR 161.013-7)을 따른다.
- 일반 메시지는 국제 산악 조난 신호(분당 6회)를 쓰고, 응답은 분당 3회로 보낸다.
- 구조대가 접근하면 이중 점멸로 정확한 차량 위치를 알린다.
- 차량마다 제어 가능한 조명이 다르므로 Capability API로 확인해 조명을 고른다. 후방 안개등이 있으면 상향등과 후방 안개등을 점멸하고, 하향등은 켜둔다. 없으면 하향등과 상향등을 함께 점멸한다. 하향등이 켜질 때 미등도 같이 켜져 뒤쪽에도 신호가 간다.
- 점멸 명령을 보낸 뒤 실제 점등 상태를 다시 읽어 확인한다. 신호가 끝나면 모든 조명을 원래 상태로 되돌린다.
- 앱이 없는 사람이나 헬기, 드론도 알아볼 수 있는 국제 관례를 따른다. 일정한 1~2Hz 점멸은 비상등으로 오인되므로 쓰지 않는다.

**③ 차량 간 중계 — 정차 차량 행렬이 통신망이 된다**
- 신호를 받은 차량은 무작위로 1.5~6초를 기다렸다가 같은 메시지를 다시 보낸다. 최대 3대까지 이어진다.
- 같은 메시지는 한 번만 중계해 신호가 무한히 반복되지 않게 한다.
- 내가 보낸 메시지가 다른 차를 거쳐 돌아오면 "중계 확인"으로 표시한다. 메시지가 전달됐다는 간접 확인이 된다.

**④ 재난 유형 모드 13종 — 재난마다 해야 할 일이 다르다**
- 일반, 지진, 산불, 호우·침수, 태풍·강풍, 대설·한파, 폭염, 화학사고, 방사능, 공습·민방공, 터널 사고, 산사태·낙석, 정전·통신 장애.
- 고르면 행정안전부 국민행동요령 중 차 안에서 할 일과 하지 말 일을 오프라인으로 보여 준다. 공식 국내 지침이 없는 항목만 해외 정부 자료로 채우고, 근거가 없거나 출처끼리 충돌하는 내용은 넣지 않았다. 화면 아래에 출처 기관을 적는다.
- 첫 화면의 메시지 5개가 상황에 맞게 바뀐다(예: 대설·한파 → 추위·저체온, 고립, 연료·전력, 식량, 응급 환자).
- 앱 동작도 바뀐다. 공습 모드는 등화관제(외부 조명 끔)를 자동으로 켠다. 화학사고·산불·방사능 모드는 "창문을 열면 더 멀리 들려요" 안내를 끄고 "창문을 닫아 두세요"로 바꾼다.

**⑤ 사람에게 직접 알리기**
- 위급 메시지는 데이터 신호 뒤에 모스 SOS 소리(1kHz, ITU 타이밍)를 붙인다. 앱이 없는 보행자와 구조대도 알아듣는다. 이 소리는 데이터로 오인되지 않도록 설계했다.
- 받은 신호를 음성으로 읽어 준다. "차량 1대를 거쳐 응급 환자 2명 신호를 받았어요. 남동쪽 약 150미터." 기기 TTS를 먼저 쓰고, 없으면 Pleos TextToSpeech SDK(기기 내장 모드, 네트워크 불필요)를 쓴다.
- QR 전달: 보낸 구조 요청을 QR 코드로 띄운다. 앱이 없는 보행자나 구조대가 휴대폰으로 찍어 통신이 되는 곳에서 열면 구조 서버로 전달된다. 주변에 이 앱을 쓰는 차량이 없어도 구조 요청이 밖으로 나갈 수 있다.

**⑥ 차량 에너지 관리**
- Vehicle SDK로 배터리·연료 잔량을 읽어 "지금처럼 쓰면 약 10일 버틸 수 있어요(추정)"를 보여 준다.
- 6시간 미만이면 불빛을 끄고 소리만 쓰도록 안내한다.
- 난방 아끼며 버티기(전기차): 구조를 기다리는 동안 가장 큰 전력 소비는 난방이다. 히터를 12~16도 사이에서 켰다 껐다 하고, 전력을 훨씬 덜 쓰는 시트·핸들 열선으로 보완한다. 좌석 감지로 사람이 앉은 자리만 데운다. 공기가 탁해지지 않게 인원에 맞춰 10분마다 일정 시간 바깥 공기를 넣고, 화학사고·방사능·산불 모드에서는 바깥 공기를 들이지 않는다.
- 시작 전에 "지금처럼 22도로 틀면 약 N시간 / 아껴 쓰면 약 M시간"을 보여 준다. 차량이 바깥 온도를 알려 주지 않아 영하 15도(한파경보 기준)·저항식 히터로 가정해 짧게 잡는다. 이 가정에서 54kWh·2인 기준 약 22시간이 약 25시간으로 늘어난다. 바깥이 덜 추울수록 늘어나는 비율이 커진다.
- P단에서 사용자가 시작했을 때만 제어하고, 멈추거나 P단을 벗어나면 시작 전 공조 설정으로 되돌린다.

**⑦ 통신이 살아 있을 때 — 미리 알고, 미리 받아 두고, 바로 닿는다**
- 재난 자동 인식: 구조 서버가 행정안전부 긴급재난문자를 받아 재난 유형으로 분류한다. 내 지역에 문자가 오면 앱이 문자 내용과 함께 "‘산불’ 행동요령 보기"를 띄운다.
- 대피소 미리 받아 두기: 주변 대피소(행정안전부 통합대피소·민방위대피소)를 기기에 저장한다. 통신이 끊긴 뒤에도 "동쪽 약 50m"처럼 방향과 거리를 보여 준다.
- 상황에 맞는 대피소: 재난마다 가야 할 곳이 다르다. 공습 모드는 지하 민방위대피소, 지진 모드는 옥외대피장소, 한파·폭염 모드는 쉼터를 먼저 보여 준다. 민방위대피소는 면적 기준 수용 인원(약 N명)을 함께 표시한다.
- 재난문자 선별: 실제 재난문자의 다수는 실종자 찾기, 단수 안내, 예방 캠페인이다. 진행 중인 재난만 골라 보여 준다.
- 온라인 구조 요청: 보낸 요청은 소리·빛과 함께 구조 서버로도 간다. 소리가 닿지 않는 먼 곳의 구조 요청도 서버에서 받아 소리로 받은 신호와 같은 카드에 "북동쪽 약 2.2km"로 표시한다.
- 구조 상황판: 구조기관이 보는 지도 화면. 구조 요청이 위치·종류·인원·확인한 차량 수와 함께 표시된다.
- 통신이 끊기면 상단에 "통신 끊김 · 소리와 빛으로"가 뜨고, 받은 구조 요청과 내가 보낸 요청은 기기 안에 암호화해 보관한다(AES-256-GCM, 7일). 통신이 돌아오면 자동으로 서버에 보낸다. 두절 구역 안의 구조 요청이 차량을 타고 밖으로 나온다.
- 공공 API 키는 서버에만 두고, 앱은 약 1km로 줄인 위치만 서버에 보낸다.

**⑧ 화면을 닫아도 계속 듣는다**
- 수신·중계 엔진이 포그라운드 서비스로 동작한다. 내비게이션을 보거나 다른 앱을 써도 주변 신호를 받고 이어서 전달한다.

**⑨ 안전 잠금**
- 기어가 P단일 때만 송신한다. P단에서 벗어나면 즉시 중단하고 조명을 원래 상태로 되돌린다.
- 등화관제 모드: 야간 공습경보 때는 행동요령에 따라 외부 조명을 끄고 소리로만 통신한다.
- 조난 점멸 패턴은 실제 조난 상황에만 쓰도록 메시지 종류와 연결해 둔다.

**차량 특화 요소**

| 차량 자원 | 활용 |
|---|---|
| 외부 조명 (Vehicle SDK Light) | 수 km 밖에서 보이는 조난 점멸 |
| 실내 스피커·마이크 | 별도 장비 없는 데이터 송수신 |
| 기어 상태 (Vehicle SDK Gear) | 정차 확인, 안전 잠금 |
| 배터리·연료 (Vehicle SDK EvBattery·Fuel) | 신호 지속 시간 추정, 절전 안내 |
| 히터·시트 열선·핸들 열선 (Vehicle SDK HVAC·Seat·SteeringWheel) | 구조 대기 중 난방 전력 절약 |
| 좌석 감지 (Vehicle SDK Seat) | 인원 기본값, 열선을 켤 자리 선택 |
| GPS | 통신 없이 구조 위치 전달 |
| 대용량 배터리 | 휴대전화가 꺼진 뒤에도 신호 유지 |
| 도로 위 위치 | 정차 차량 행렬이 그대로 중계망이 됨 |

## 4. 주요 사용 시나리오

**시나리오 A — 산불로 고립된 산간 도로**
1. 산불로 도로가 막히고 휴대전화가 끊긴다. 차량 5대가 1km 구간에 멈춰 있다.
2. 맨 앞 차량 A의 동승자가 연기를 마시고 쓰러진다. 운전자가 P단 상태에서 `응급 환자`를 누르고 인원을 2명으로 맞춘다.
3. A는 소리 신호를 3회 보내고, 상향등과 후방 안개등으로 SOS를 점멸한다.
4. 뒤쪽 차량 B가 신호를 받는다. 화면에 "응급 환자 2명, 북쪽 약 200m, 가까운 차량"이 뜨고 음성으로도 읽어 준다. B가 자동으로 중계한다.
5. C, D를 거쳐 메시지가 진입로에 도착한다. 대기 중이던 소방차 옆 차량 E의 화면에 "응급 환자 · 3대 거쳐 중계"가 표시된다.
6. A의 화면에는 "내 신호를 다른 차량이 이어서 전달했어요"가 뜬다. 구조대가 접근하면 A는 `구조대 접근` 이중 점멸로 위치를 알린다.
7. 진입로 밖에서 통신이 되는 차량 E가 그동안 받은 구조 요청을 위치와 함께 구조 서버로 올린다.

**시나리오 B — 공습경보로 정차한 도로**
1. 공습경보가 울리고 차량들이 도로 우측에 정차한다. 기지국은 정전으로 멈췄다.
2. 운전자가 상황을 `공습·민방공`으로 고른다. 등화관제가 자동으로 켜져 조명은 꺼지고 소리 신호만 쓴다. 화면 위쪽에 "도로 오른쪽에 세우고 키를 둔 채 대피하세요" 행동요령이 뜬다.
3. 노약자를 태운 차량이 `노약자·어린이 동승 · 4명`을 보낸다. 주변 차량이 중계하고, 대피를 돕는 민방위 요원 차량이 받는다.
4. 경보가 해제되면 대피소를 확인한 차량이 `대피소 있음`을 위치와 함께 보내 다른 차량에 알린다.

**시나리오 C — 폭설로 고립된 고속도로**
1. 폭설로 차량 수십 대가 고속도로에 갇히고 통신이 끊긴다. 운전자가 상황을 `대설·한파`로 고른다.
2. "고립되면 차 안에서 기다리고, 배기구 주변 눈을 자주 치우세요" 안내와 일산화탄소 위험이 표시된다.
3. 어르신이 탄 차량이 `추위·저체온 · 2명`을 보낸다. 연료가 남은 차량들이 받아 이어서 전달한다.
4. 화면 위쪽에 "연료 18% · 지금처럼 쓰면 약 11시간"이 보여, 운전자가 공회전 시간을 판단한다.

## 5. 개발 계획

**구조**

```
[화면 · Compose]  보내기 / 받은 신호 / 상황·행동요령 / 설정
        │
[SignalEngine]  앱 프로세스 전체 수명, 포그라운드 서비스(마이크·위치)가 유지
        │
 ┌──────┼─────────────┬──────────────┬──────────────┬──────────────┐
[음향 모뎀]       [조명 신호]     [차량 연동]     [재난 모드]     [구조 서버 전달]
 프레임 v1 부호화   SOS·비컨 패턴   Light·Gear      13종 행동요령    암호화 보관함
 16-FSK·처프 동기   조명 선택·복원  EvBattery·Fuel  우선 메시지      HTTPS 전송
 RS(15,9)×2 교차    등화관제        Capability      창문·등화 동작
        │
 AudioTrack(USAGE_ALARM) / AudioRecord(UNPROCESSED) / GPS / TTS
```

**음향 프레임 설계**

| 항목 | 값 |
|---|---|
| 정보 | 버전 2bit · 메시지 5bit · 인원 4bit · 차량 ID 8bit · 순번 4bit · 중계 횟수 2bit · 위도 19bit · 경도 20bit + CRC-8 (72bit) |
| 오류 정정 | Reed-Solomon (15, 9) / GF(16) 두 개를 심볼 단위로 교차 배치. 부호마다 오류 3개 또는 소거 6개 정정, 연속 잡음은 두 부호에 나뉨. CRC로 맞는 조합만 채택 |
| 변조 | 16-FSK, 1,500~3,437Hz, 125Hz 간격, 홀짝 심볼 62.5Hz 엇갈림, 심볼 80ms + 보호 구간 20ms |
| 동기 | 1~5kHz 선형 처프 256ms, FFT 정합 필터 |
| 복조 | 심볼별 Goertzel, 신뢰도 낮은 심볼을 소거로 처리해 재복호 (GMD 복호) |
| 길이 | 프레임 3.3초, 3회 반복 송신 |
| 수신 처리 | 마이크 잡음 억제·자동 음량·반향 제거 해제, 800Hz~6kHz 대역 통과, 44.1kHz 기기 호환 |

대역은 가청 1.5~3.5kHz를 쓴다. 차량 핸즈프리 마이크 경로가 7kHz 이하로 설계되는 경우가 많고(ITU-T P.1110), 공기 흡수가 3kHz에서 0.015dB/m로 19kHz(0.38dB/m)보다 25배 작다(ISO 9613-1). 엔진·노면 소음은 저역에 몰려 있다. 재난 상황에서는 소리가 들리는 편이 오히려 낫다.
변조 방식 비교 실측 연구(Putz et al., ACM TIoT 2026)에서 처프 계열 방식은 40m에서 98% 이상 성공했고, 다중 톤 방식(ggwave 가청 모드)은 주변 소음 속에서 실패했다. 이 앱은 처프로 동기를 잡고 심볼당 단일 톤만 보내 톤 하나에 송신 전력을 모은다.

시뮬레이션 결과 (잔향 2경로, 엔진 저주파, 백색 잡음, 프레임당 40회 시험):

| 전대역 SNR | 0dB | -5dB | -10dB | -15dB | -20dB |
|---|---|---|---|---|---|
| 수신 성공률 | 100% | 100% | 100% | 100% | 32.5% |

| 조건 | 결과 |
|---|---|

실측 한계(-13.7dB 성공, -19.7dB 실패)는 시뮬레이션 결과(-15dB 100%, -20dB 32.5%)와 일치한다.
- 확인하지 못한 항목:
  - 상향등 실제 점등: 에뮬레이터에 차량 제어기 모델이 없어 스위치 명령 수락까지만 확인된다.
  - Pleos TTS 음성 재생: 에뮬레이터에서 초기화는 성공했지만 재생 응답이 없다. 기기 TTS가 있는 차량에서는 그쪽을 쓴다.
  - 세로 폼팩터: 앱은 세로일 때 보내기·받기를 위아래로 쌓도록 구현했지만, Pleos 폼팩터 시험 도구로는 아직 확인하지 않았다.
  - 차량 간 실외 전달 거리: 실차에서 측정해야 한다.
- 운용 조건: 차량 전원(ACC 이상)이 켜져 있어야 한다. 차량 간 거리가 멀면 창문을 조금 열어야 수신 거리가 늘어난다. 차체 차음이 25~35dB에 이르기 때문이다.
- 공공 API(긴급재난문자·통합대피소·민방위대피소)는 실제 응답으로 확인했다. 구조 상황판 화면은 API까지만 확인했다.
- 2차 PT까지: 시나리오 A·B·C 시연 영상, 실차·실외 거리 측정, 평시 점검·훈련 모드, 구조 서버 배포.

## 6. 기대효과 및 발전 가능성

- **사용자 가치:** 통신이 끊긴 순간에도 차 안에서 구조 요청을 보낼 수 있고, 내 신호가 전달됐는지 확인할 수 있다. 별도 장비 없이 이미 가진 차량으로 해결한다.
- **탑재 방식:** 차량 기본 안전 기능으로 탑재하는 것을 목표로 한다. 같은 앱을 가진 차량이 늘어날수록 중계망이 촘촘해진다.
- **평시 사용:** 월 1회 신호 점검(조명·스피커 자가 진단)과 민방위 훈련일 신호 연습 모드를 둔다. 둘 다 통신망 없이 동작한다.
- **확장:**
  - LTE-V2X(C-ITS 단일 표준, 2023.12 결정)가 보급되면 같은 메시지 체계를 V2X 메시지로 옮길 수 있다.
  - 구조기관 차량과 드론을 수신 노드로 쓸 수 있다.
  - 스마트폰 카메라로 조난 점멸을 해독하는 보조 앱을 붙일 수 있다.
