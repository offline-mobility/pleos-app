# Offline Mobility 제품 기획

## 한 줄 정의

기지국과 인터넷이 끊긴 재난 상황에서 정차한 차량끼리 표준화된 광학·음향 신호로 최소한의 생존 정보를 주고받는 차량용 앱입니다.

## 문제 정의

- 대상 사용자: 산불, 폭우, 대규모 정전 등으로 도로에서 고립된 운전자와 탑승자
- 차량 안에서 발생하는 문제: 휴대전화 통신이 끊기면 주변 차량에 구조 요청이나 도로 위험을 정확히 전달하기 어렵습니다.
- 기존 해결 방식의 한계: 경적과 상향등은 주의를 끌 수 있지만 의미가 표준화되지 않아 오해하기 쉽습니다.

전쟁만을 전면에 내세우지 않고, 통신 인프라가 손상될 수 있는 모든 재난과 비상 안보 상황을 포괄합니다.

## MVP 사용자 시나리오

1. 차량이 정차 상태인지 확인합니다.
2. 사용자가 `긴급 구조 요청`, `차량 이동 불가`, `응급 환자`, `식수 요청`, `도로 차단`, `안전 경로` 중 하나를 선택합니다.
3. 광학 신호 또는 음향 신호 채널을 선택합니다.
4. 앱이 선택된 메시지를 짧고 긴 펄스 패턴으로 변환해 미리 보여줍니다.
5. 정차 상태일 때만 송신을 시작합니다.
6. 수신 차량은 같은 패턴을 감지해 표준 메시지로 복원합니다.

## 현재 구현 범위

- 차량용 960×540 가로 화면에 맞춘 Compose UI
- 6개의 재난 메시지 프리셋
- 모스 기반 신호 펄스 인코더
- 광학·음향 채널 선택
- 송신 진행 상태와 수신 시뮬레이션
- 주행 상태에서 송신을 차단하는 안전 잠금 데모
- Pleos Vehicle SDK 초기화 및 연결 상태 표시

## 기술 검증이 필요한 범위

아래 기능은 공식 SDK의 실제 제어 가능 범위와 공모전 운영 정책을 확인한 뒤 연결합니다.

| 기능 | 목표 | 현재 상태 |
|---|---|---|
| 기어 상태 | P단 또는 안전 정차 상태 확인 | UI 데모, Vehicle API 매핑 필요 |
| 외부 조명 | 차량 외부 광학 신호 송신 | Capability 및 쓰기 권한 검증 필요 |
| 차량 오디오 | 비프음 기반 음향 신호 송신 | 오디오 출력 정책 검증 필요 |
| 마이크 수신 | 특정 주파수와 길이를 분석 | Android/Pleos 마이크 정책 검증 필요 |
| 카메라 수신 | 밝기 변화로 광학 패턴 분석 | 카메라 접근 가능 여부 검증 필요 |

물리 경적, 창문 자동 개방, 주행 중 외부등 점멸은 안전성과 API 제공 여부가 확인되기 전에는 제품 기능으로 약속하지 않습니다.

## 안전 원칙

1. 외부 신호 송신은 정차 상태에서만 허용합니다.
2. 주행 중에는 수신 메시지를 짧은 문장과 음성으로만 안내합니다.
3. 사용자가 직접 송신을 시작하며 자동 반복 송신은 기본값으로 두지 않습니다.
4. 지원되지 않는 차량 기능은 시뮬레이션과 실제 제어를 명확히 구분합니다.
5. 구조기관의 공식 경보나 긴급 통신을 대체한다고 표현하지 않습니다.

## MVP 완료 기준

- Pleos Connect Emulator에서 앱이 실행됩니다.
- 프리셋 선택부터 신호 인코딩, 송신 완료까지 한 화면에서 시연할 수 있습니다.
- 주행 데모 상태에서는 송신 버튼이 비활성화됩니다.
- Vehicle API 실패 또는 미연결 상태가 화면에 표시됩니다.
- 신호 프로토콜 단위 테스트와 Debug APK 빌드가 통과합니다.
